# Phase 21.1 — Ground Truth and Evaluation Validation

## Reference source

The PRISM adapter exposes `expected_geometry.json`, `expected_components.json`, `expected_netlist.json`, `expected_stats.json`, and `expected_schematic_components.json` separately from image loading. `summarize_reference_geometry()` records whether outline, pads, vias, segments and zones exist and labels them as PRISM/KiCad-derived references, not native-parser output. The native `kicad-cli` executable is not present in the inspected development environment; the Phase 21.1 code does not claim to parse arbitrary KiCad PCB files.

Observed PRISM reference fields include pad centers/size/layers/net, trace segment endpoints/width/layer/net, via position/diameter/layers/net, zone polygons/layer/net, and component positions/rotations/footprints/pin nets. Outline geometry is empty in the inspected reference schema. Availability varies by board and field; exact per-board counts are recorded in the generated registration inventory.

## Image-space references

`project_reference_geometry()` accepts only an independently `VERIFIED` transform from KiCad mm to an image frame and matching board side. It labels output `PROJECTED_NOT_VISIBILITY_GROUNDED` and records `UNKNOWN_OCCLUSION_NOT_MODELED`. Separate masks are generated by geometry class, not combined with model predictions. The visibility mask remains `NOT_AVAILABLE`; design copper hidden by soldermask, components or other material cannot be scored as visible photo copper without separate annotation.

Build the record with:

```bash
python scripts/build_pcb_reference.py --registration data/benchmarks/phase21_1/registration/summary.json --all
```

Unverified views are kept in the report and are not projected. The PRISM PCB reference netlist is design truth for that rendered example only; it is not independent physical continuity evidence.

## Leakage controls

- Image inference loads input images/design data permitted by its named track; it must not load evaluation references.
- `load_references()` is a separate evaluation-stage operation.
- `IMAGE_ONLY` supplies photo pixels only to the reconstruction algorithm. An externally held transform may be used for scoring only if it is excluded from inference.
- `DESIGN_ASSISTED` reports the exact design metadata used; its scores are reported separately.
- Calibration and held-out validation point IDs must be disjoint.
- Labels used to fit registration cannot also establish independent registration accuracy or image-only reconstruction performance.
- Existing PRISM pixel candidate fractions are not accuracy scores.

## Current evidence and Phase 21.2 gate

The pinned PRISM inventory is structurally complete at 12/12 samples, but its available coordinate references do not currently supply reviewed image-to-design correspondences or held-out calibration truth. The image detector's candidate counts are diagnostic only. Accordingly, registration errors, success rate, TOP/BOTTOM consistency, pad F1, trace precision/recall/IoU and electrical edge/net accuracy remain `NOT_VERIFIED` for the current Phase 21.1 attempt.

PRISM is sufficient for controlled code-path and design-reference schema checks. It is not yet sufficient for an independent image-space geometry score or physical-board generalization claim. Phase 21.2 may prepare annotation instructions, but quantitative image-only label construction/evaluation should wait for verified alignment and independent visibility adjudication. For real-board work, obtain matching board revision/images/design files, reviewed calibration and held-out points, layer-aware vias/tracks, and independently reviewed pin/pad/net truth. Vision model training is not justified by the current evidence alone.
