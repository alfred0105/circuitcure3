# Phase 21 Roadmap

Phase 21 now prioritizes a PCB-photo-to-repair workflow: **image integration → component detection/identity → functional-block candidates → symptom-driven fault candidates → measurements and electrical evidence → fault overlay on the PCB image**. Full PCB netlist reconstruction is an optional evidence-backed input path; it is not required for the main product workflow. No visual candidate is an electrical fact or a confirmed fault.

The independently evaluated research tracks remain component recognition on board-grouped data, physics-informed fault reasoning, and active-measurement efficiency. Evidence states are claim-specific. A successful model load or software test is not a physical performance result.

## Phase 21.2 direction update

The original Phase 21.2 plan prioritized board-level annotations, grouped dataset splits, and Ground Truth before a multiview application path. The implementation sequence has changed: first build a bounded local backend that accepts multiple same-board photos, registers photos only within the same declared side, emits a conservative mosaic and candidate component map, and returns a fault-overlay contract. This does not remove or relax the independent-label requirements in Phases 21.3–21.5. Photo-to-photo alignment is not KiCad alignment; image detections are candidate observations; inferred mosaics do not establish board geometry or electrical connectivity. Without independently reviewed real-board data, component accuracy remains `NOT_EVALUATED`.

## Direction change and retained connectivity work

Earlier Phase 21 planning treated image-to-design reconstruction and electrical connectivity as the central route through Phases 21.3–21.5. The product path has changed to photo-based component mapping and symptom-led repair support. Those earlier investigations and modules are retained as optional design-assisted/electrical evidence sources, available when matching designs and independently verified correspondence exist. They do not gate the photo-to-component workflow and cannot silently supply confirmed physical connections. Historical records remain available in the earlier Phase 21.0–21.2 reports.

Component recognition/functional-block work (21.3–21.4) and electrical-model/measurement work (21.6–21.7) may proceed in parallel on distinct datasets. Fault localization and measurement-feedback integration must consume explicit evidence and preserve uncertainty. When connectivity is unavailable, the app may provide symptom-based component/block candidates, but it must not infer confirmed net membership or SPICE-ready wiring from the photo map.

For 21.8, evaluate natural-language symptom structuring, fault-candidate accuracy, and secondary-impact candidates separately. For 21.9, evaluate task completion and usability separately from AI accuracy. Keep physical damage observation distinct from simulated rating stress.

## Immediate Phase 21.1 gate

Phase 21.1 has added a provenance bundle schema, explicit coordinate frames, a correspondence-only RANSAC fitter, independent error/status records, and guarded design-reference projection. Pinned PRISM inventory is available at 12/12 boards; the initial run records 24 image sides as `REGISTRATION_UNVERIFIED`, because image candidates are not independently adjudicated correspondences. No matching physical CircuitCare photo + KiCad PCB/Position CSV + electrical reference set or held-out calibration points are present. Quantitative reconstruction claims remain blocked until these inputs exist. Do not use PRISM pixel candidate fractions as accuracy targets.

The first substantive technical blocker is therefore data provenance and image-to-design registration, followed by independently adjudicated connectivity ground truth. In parallel, diagnosis work can continue on explicitly synthetic/design tracks, and measurement policy evaluation can be prepared on frozen simulated cases without making physical efficiency claims.
